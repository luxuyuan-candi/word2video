# Word2Video PC Web 应用页面功能设计

## 1. 文档目标

本文档用于定义 Word2Video PC Web 应用的首版页面功能设计，作为后续前端开发、接口联调、交互验收和任务拆分的基础。

当前产品重点不是直接生成最终视频文件，而是协助用户以“项目”为单位，把一个或多个文字剧本持续转化为可用于 AI 视频生产的结构化素材包，包括项目级知识图谱、实体对象模型图、视频帧文字描述和帧级参考图片关联。

后续任何功能规则、页面流程、数据结构或导出格式的调整，都需要同步更新本文档，确保产品设计文档始终作为当前功能实现的事实来源。

## 2. 产品定位

Word2Video 是一个面向 PC 用户的 AI 视频前期制作工具。用户创建项目后，可以在同一个项目下持续新增剧本。平台会基于项目内的剧本内容持续更新知识图谱，提取人物、物品、场景等实体对象，并引导用户为这些实体对象生成或上传参考图片。

最终，平台输出一份结构化创作资产：项目级知识图谱、项目级实体对象模型图片、当前剧本或总剧本的视频分帧文字描述，以及每一帧关联的实体参考图。用户可以把这些内容带到其他 AI 图像或视频平台中继续生成画面和视频。

## 3. 目标用户

- AI 视频创作者：需要把剧本拆解成可执行的画面生成素材。
- 短片/故事创作者：希望保证人物、物品和场景在多帧画面中保持一致。
- 内容运营人员：需要批量把文案、广告脚本、口播脚本整理为视频生成提示词。
- 教育/培训内容生产者：需要把课程脚本拆分为清晰的画面描述。
- AI 工作流用户：熟悉 Midjourney、Stable Diffusion、Runway、可灵、即梦等外部生成工具，需要更稳定的前期素材管理。

## 4. 核心业务流程

```text
创建或打开项目
  ↓
输入或追加文字剧本
  ↓
平台解析剧本内容
  ↓
更新项目级知识图谱并编织对象关系
  ↓
识别并合并人、物、场景等实体对象
  ↓
引导用户为项目级实体对象生成或上传参考图片
  ↓
沉淀项目级知识图谱与实体对象模型图片
  ↓
按当前剧本或总剧本划分视频帧文字描述
  ↓
为每一帧关联相关实体参考图
  ↓
按当前剧本或总剧本导出结构化素材包，供外部平台继续生成画面
```

## 5. 首版功能范围

### 5.1 包含功能

- 文字剧本输入与编辑。
- 项目级剧本管理，支持同一项目下新增多个剧本。
- 剧本解析任务提交。
- 项目级知识图谱生成、增量更新与可视化展示。
- 实体对象识别，包含人物、物品、场景等类型。
- 实体对象跨剧本合并，避免同一项目下重复生成同一人物、物品或场景。
- 实体对象详情查看与编辑。
- 引导用户为实体对象生成模型参考图片。
- 支持用户输入图片生成提示词。
- 支持用户上传自己的参考图片。
- 实体图片生成结果预览、选择和重新生成。
- 支持对“当前剧本”或“总剧本”分帧，生成每一帧的文字描述。
- 每一帧关联相关实体对象和实体参考图片。
- 支持对“当前剧本”或“总剧本”导出最终素材包。
- 导出素材以帧为粒度组织，每个帧目录使用数字编号命名，并包含帧场景描述和相关实体对象图片。
- 项目历史列表和项目详情恢复。

### 5.2 暂不包含功能

- 直接生成最终视频文件。
- 复杂时间线剪辑。
- 音频、配音和字幕合成。
- 多人协作。
- 商业化额度、支付和会员系统。
- 移动端专项适配。

## 7. 页面设计

### 7.1 项目工作台页

页面目标：让用户在一个页面内完成从剧本输入到素材包导出的核心流程。

建议路径：`/`

#### 页面布局

PC 端采用三栏工作台布局：

- 左侧：流程步骤导航和项目状态。
- 中间：当前步骤的主要编辑区。
- 右侧：上下文预览、详情面板和操作建议。

推荐布局：

- 左侧宽度：240px。
- 中间区域：自适应主工作区。
- 右侧宽度：360px 到 420px。
- 页面最小适配宽度：1366px。

#### 步骤导航

| 步骤 | 说明 |
| --- | --- |
| 1. 剧本管理 | 用户创建项目、输入首个剧本，或在已有项目下新增剧本 |
| 2. 解析图谱 | 平台分析当前新增剧本，并增量更新项目级知识图谱 |
| 3. 确认实体 | 用户查看并修正项目级人物、物品、场景等实体 |
| 4. 生成模型图 | 用户为项目级实体对象生成或上传参考图片 |
| 5. 生成分帧 | 平台按“当前剧本”或“总剧本”拆分视频帧文字描述 |
| 6. 导出素材 | 按“当前剧本”或“总剧本”导出帧级素材目录 |

### 7.2 剧本管理页/步骤

页面目标：以项目为单位管理多个剧本，支持新增剧本、选择当前剧本，并启动针对当前剧本的解析。

#### 核心模块

| 模块 | 功能说明 |
| --- | --- |
| 项目信息 | 展示项目名称、总剧本数、实体数、已配图实体数、分帧数 |
| 剧本列表 | 展示同一项目下的所有剧本，支持切换当前剧本 |
| 当前剧本编辑器 | 支持输入、粘贴、清空、字数统计 |
| 剧本标题 | 每个剧本独立标题，默认根据内容生成，可手动修改 |
| 内容类型 | 可选故事短片、广告脚本、教育讲解、产品介绍等 |
| 新增剧本 | 在当前项目下追加新的剧本文本 |
| 解析按钮 | 校验当前剧本后提交解析任务，并增量更新项目级资产 |
| 示例入口 | 提供示例剧本，便于用户快速体验 |

#### 输入校验

| 字段 | 规则 |
| --- | --- |
| 项目标题 | 首次创建项目时必填或自动生成 |
| 剧本标题 | 可选，缺省时自动生成 |
| 剧本文字 | 必填，建议 100 到 10000 字 |
| 内容类型 | 可选，用于辅助解析 |

#### 页面状态

| 状态 | 页面表现 |
| --- | --- |
| 初始状态 | 展示项目创建入口、剧本编辑器和示例入口 |
| 已有项目状态 | 左侧展示项目剧本列表，中间展示当前剧本编辑器 |
| 可解析状态 | 当前剧本达到最小字数后，解析按钮可点击 |
| 解析中 | 展示“分析当前剧本、抽取新增实体、合并已有实体、更新关系”等阶段 |
| 解析失败 | 展示失败原因和重新解析按钮 |

#### 项目级素材共用规则

- 同一项目下的所有剧本共用一份知识图谱。
- 同一项目下的所有剧本共用一份实体对象清单。
- 同一项目下的所有剧本共用实体模型图片，避免同一人物、物品、场景重复生成参考图。
- 新增剧本解析后，平台应基于已有知识图谱和实体资产做增量更新。
- 当新增剧本识别到疑似已有实体时，应优先合并到已有实体，并允许用户手动拆分或合并。
- 当前剧本用于聚焦本次新增内容；总剧本用于查看项目完整叙事和整体素材沉淀。

### 7.3 知识图谱页/步骤

页面目标：把项目中所有剧本沉淀出的对象、事件和关系可视化，帮助用户理解项目级知识图谱，并查看当前剧本对图谱带来的新增或变更。

#### 核心模块

| 模块 | 功能说明 |
| --- | --- |
| 图谱画布 | 展示实体节点和关系连线 |
| 增量变更标识 | 标记当前剧本新增节点、新增关系、更新过的实体描述 |
| 节点筛选 | 按人物、物品、场景、事件筛选 |
| 节点搜索 | 快速定位某个实体对象 |
| 图谱详情面板 | 点击节点后展示实体信息和相关关系 |
| 关系说明 | 展示对象之间的关系类型和来源文本 |

#### 图谱节点类型

| 类型 | 示例 |
| --- | --- |
| 人物 | 主角、配角、旁白角色 |
| 物品 | 道具、装备、产品、关键物件 |
| 场景 | 城市、房间、学校、办公室、自然环境 |
| 事件 | 相遇、冲突、转折、行动、结尾 |
| 概念 | 品牌、主题、情绪、风格关键词 |

#### 主要交互

1. 用户查看图谱整体结构。
2. 点击节点，右侧展示该对象的描述、关系和出现位置。
3. 用户可修改实体名称、类型、描述。
4. 用户可删除误识别实体，或手动新增实体。
5. 用户可查看当前剧本新增内容对项目图谱的影响。
6. 用户确认图谱后进入实体对象确认步骤。

#### 增量更新规则

- 新增剧本解析后，知识图谱不应整体覆盖，而应在项目级图谱上增量更新。
- 已存在的实体节点应保留原有 ID、主图和用户编辑过的描述。
- 新增关系需要记录来源剧本和来源文本，方便用户追溯。
- 当系统无法判断两个实体是否为同一对象时，应标记为“待确认合并”。

### 7.4 实体对象确认页/步骤

页面目标：让用户确认项目中需要保持视觉一致性的实体对象。实体对象是项目级资产，供同一项目下所有剧本共用。

#### 核心模块

| 模块 | 功能说明 |
| --- | --- |
| 实体列表 | 按类型展示人物、物品、场景等对象 |
| 实体卡片 | 展示名称、类型、描述、出现剧本数、出现次数、图片状态 |
| 实体编辑面板 | 修改实体名称、类型、外观描述、补充说明 |
| 合并建议 | 展示疑似重复实体，支持用户确认合并或保留 |
| 批量操作 | 批量确认、批量忽略、按类型筛选 |

#### 实体卡片状态

| 状态 | 说明 |
| --- | --- |
| 待确认 | 平台识别到但用户未确认 |
| 已确认 | 用户确认该实体需要进入后续生成 |
| 已忽略 | 用户认为该实体不需要生成参考图 |
| 待生成图片 | 实体已确认但没有参考图片 |
| 已有图片 | 实体已绑定至少一张参考图片 |
| 待确认合并 | 系统认为该实体可能与已有实体重复，需要用户确认 |

### 7.5 实体参考图生成页/步骤

页面目标：引导用户为每个实体对象生成或上传模型参考图片。

#### 页面布局

- 左侧：实体对象列表和生成状态。
- 中间：当前实体的图片生成工作区。
- 右侧：实体描述、提示词、参考图片和生成历史。

#### 核心模块

| 模块 | 功能说明 |
| --- | --- |
| 当前实体信息 | 展示实体名称、类型、剧本描述和关系摘要 |
| 提示词编辑器 | 用户可输入或修改图片生成提示词 |
| 自动提示词建议 | 平台根据实体描述生成提示词草稿 |
| 参考图片上传 | 用户上传自己的图片作为参考 |
| 图片生成按钮 | 调用 AI 图片生成能力 |
| 生成结果画廊 | 展示多张候选图片 |
| 图片预览 | 放大查看图片细节 |
| 选为模型图 | 将某张图片设为该实体的主参考图 |
| 重新生成 | 基于当前提示词再次生成 |

#### 实体类型生成重点

| 实体类型 | 生成重点 |
| --- | --- |
| 人物 | 年龄、性别、服装、发型、表情、身份、风格一致性 |
| 物品 | 形状、材质、颜色、品牌感、使用场景 |
| 场景 | 空间结构、时间、光线、氛围、地点特征 |
| 概念 | 视觉符号、色彩、情绪和抽象表达 |

#### 主要交互

1. 用户选择一个待生成图片的实体。
2. 平台根据实体描述生成默认提示词。
3. 用户可以修改提示词。
4. 用户可以上传参考图片。
5. 用户点击生成图片。
6. 平台返回候选图片。
7. 用户预览候选图片，并选择一张作为实体模型图。
8. 用户可继续为下一个实体生成图片。

### 7.6 视频分帧页/步骤

页面目标：根据“当前剧本”或“总剧本”生成视频帧文字描述，并为每一帧关联项目级实体对象和参考图片。

#### 核心模块

| 模块 | 功能说明 |
| --- | --- |
| 分帧范围选择 | 支持选择“当前剧本”或“总剧本” |
| 当前剧本信息 | 当选择当前剧本时，展示当前剧本标题、字数、解析状态 |
| 总剧本信息 | 当选择总剧本时，展示项目下所有剧本数量和总字数 |
| 分帧列表 | 按顺序展示每一帧 |
| 帧描述 | 展示该帧的画面文字描述 |
| 镜头信息 | 展示景别、镜头运动、视角、画面氛围等 |
| 关联实体 | 展示该帧涉及的项目级人物、物品、场景 |
| 参考图片 | 展示关联实体的模型图片 |
| 提示词复制 | 一键复制该帧画面生成提示词 |
| 帧编辑 | 用户可修改帧描述和关联实体 |

#### 帧字段

| 字段 | 说明 |
| --- | --- |
| 帧序号 | 画面顺序编号 |
| 分帧范围 | 当前剧本或总剧本 |
| 所属剧本 | 当前帧来源的剧本 ID 和剧本标题 |
| 原文片段 | 该帧来源于剧本中的哪段文字 |
| 画面描述 | 可直接用于 AI 画面生成的文字描述 |
| 镜头语言 | 景别、角度、镜头运动 |
| 情绪氛围 | 紧张、温暖、孤独、明亮等 |
| 关联实体 | 该帧出现的人物、物品、场景 |
| 参考图片 | 关联实体的模型图 |

#### 分帧范围规则

| 范围 | 说明 |
| --- | --- |
| 当前剧本 | 只对当前选中的剧本生成分帧，适合分段制作和局部迭代 |
| 总剧本 | 将项目下所有剧本按顺序合并后生成分帧，适合统一导出完整故事 |

当前剧本分帧和总剧本分帧需要分别保存，避免用户在局部迭代时覆盖完整项目分帧。

### 7.7 素材包导出页/步骤

页面目标：让用户按“当前剧本”或“总剧本”检查并导出可在其他 AI 平台继续使用的结构化素材。

#### 导出范围

| 范围 | 说明 |
| --- | --- |
| 当前剧本 | 只导出当前剧本对应的帧目录和相关实体图片 |
| 总剧本 | 导出项目下所有剧本对应的帧目录和相关实体图片 |

#### 导出内容

| 内容 | 格式建议 |
| --- | --- |
| 原始剧本 | `.txt` 或 `.md`，当前剧本导出只包含当前剧本，总剧本导出包含所有剧本 |
| 知识图谱 | `.json` 和可视化截图 |
| 实体对象清单 | `.json` 或 `.csv` |
| 实体模型图片 | 按帧复制相关 `.png`、`.jpg` 或 `.webp` 图片 |
| 分帧描述 | `.md`、`.json` 或 `.csv` |
| 帧与实体图片关联关系 | `.json` |

#### 导出选项

- 导出当前剧本完整素材包。
- 导出总剧本完整素材包。
- 仅导出实体模型图片。
- 仅导出分帧提示词。
- 复制指定帧提示词。
- 复制指定实体提示词。

#### 导出目录结构

导出的素材包必须以帧为粒度组织。每个帧目录使用数字编号命名，并包含该帧场景描述和该帧相关的实体对象图片。

推荐 ZIP 结构：

```text
export.zip
├── manifest.json
├── project.json
├── scripts/
│   ├── current-script.md
│   └── all-scripts.md
├── knowledge-graph/
│   ├── graph.json
│   └── graph-snapshot.png
└── frames/
    ├── 001/
    │   ├── scene.md
    │   ├── frame.json
    │   └── entities/
    │       ├── character_xxx.png
    │       ├── object_xxx.png
    │       └── scene_xxx.png
    ├── 002/
    │   ├── scene.md
    │   ├── frame.json
    │   └── entities/
    │       └── character_xxx.png
    └── 003/
        ├── scene.md
        ├── frame.json
        └── entities/
            ├── character_xxx.png
            └── scene_xxx.png
```

`scene.md` 应包含：

- 帧编号。
- 所属剧本标题。
- 原文片段。
- 帧场景描述。
- 镜头语言。
- 情绪氛围。
- 关联实体清单。
- 可复制到外部平台的完整画面生成提示词。

`frame.json` 应包含机器可读数据：

- 帧 ID。
- 分帧范围。
- 所属项目 ID。
- 所属剧本 ID。
- 帧序号。
- 场景描述。
- 镜头语言。

## 12. 错误与异常处理

| 场景 | 处理方式 |
| --- | --- |
| 剧本为空 | 在输入区下方提示“请输入文字剧本” |
| 剧本过短 | 提示“建议至少输入 100 个字，以便识别完整关系” |
| 解析失败 | 展示失败原因，允许重新解析 |
| 新增剧本后实体重复 | 标记为“待确认合并”，允许用户合并或保留 |
| 图谱节点过多 | 默认折叠低优先级节点，并提供筛选 |
| 实体识别错误 | 允许用户编辑、忽略或新增实体 |
| 图片生成失败 | 展示失败原因，允许调整提示词后重试 |
| 参考图片上传失败 | 提示文件格式、大小或网络问题 |
| 分帧生成失败 | 允许重新生成，并保留已确认实体资产 |
| 当前剧本未选择 | 分帧和导出当前剧本时提示用户先选择当前剧本 |
| 导出失败 | 展示失败原因，允许重新导出 |

## 13. PC 端体验要求

- 工作台需要突出流程感，让用户清楚当前处于哪个步骤、下一步要做什么。
- 项目工作台需要明确展示当前项目、当前剧本和项目总剧本之间的关系。
- 新增剧本后，需要让用户清楚哪些实体、关系和分帧来自当前剧本。
- 知识图谱画布需要支持缩放、拖拽、搜索和节点筛选。
- 实体对象列表需要适合批量处理，优先使用紧凑卡片或表格。
- 图片生成流程需要始终保留实体描述、提示词和参考图上下文。
- 分帧页面需要让用户在“当前剧本”和“总剧本”之间明确切换，并快速复制单帧提示词，同时看到关联的实体模型图。
- 导出页面需要在导出前明确展示导出范围、帧数量、涉及剧本和涉及实体图片数量。
- 页面状态切换时需要保持主要工作区尺寸稳定，避免频繁跳动。
- 删除项目、删除实体图片等危险操作需要二次确认。

### P0

## 15. 待确认问题

- 首版是否需要登录态。
- 知识图谱可视化使用前端本地布局，还是由后端返回节点坐标。
- AI 图片生成接口由平台自研、第三方服务，还是先使用 mock。
- 实体对象是否需要支持多张主参考图，例如正面、侧面、半身、全身。
- 新增剧本后实体自动合并的置信度阈值如何设定。
- 分帧粒度按镜头、按画面、按句子，还是由用户选择。
- 导出的素材包首版优先支持 `.json`、`.md`、`.csv` 中的哪些格式。
- 是否需要为不同外部平台生成不同提示词版本。
- 当前剧本导出时，是否需要同时附带项目级完整知识图谱。
- 总剧本的剧本顺序是否支持手动拖拽调整。
